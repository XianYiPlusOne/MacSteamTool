# Fluent Steam Mac

原生 macOS Steam Lua 管理器，适配 **macSteam 0.8.2 配置格式**及 **NotProton 的原生 Steam / CrossOver 前缀布局**。SwiftUI + C++ 原生桥接 + Swift Package Manager，macOS 14+，本次产物为 Apple Silicon。

## 自动入库范围（2026-11-11）

一键入库按 Steam 已有逐游戏运行器、已安装游戏分支/语言与 Steam 内容语言检查；未指定运行器时优先实际已发布的 macOS 内容，否则检查 Windows 内容。仅计入匹配平台、架构、语言、分支和所选 DLC 的仓库。共享 depot 追溯原 App，继承下载条件和清单；确认当前分支未发布的占位内容不计为缺钥，来源无法读取、加密分支或无效清单仍标记待核实。

必要内容缺钥时仍自动刷新缓存并尝试远程来源。只有实际写入后显示“已入库”；未提交的预览显示“内容缺失或待核实”或“待确认”。运行设置在检查期间变化时拒绝按旧范围写入。此检查验证入库资料，不替代实际游戏下载或启动验证。

Hades 已用真实数据完成 macOS 一键入库与独立回读；Windows 路径仍正确报告 1145362 缺钥。原有游戏配置和 Lua 保留，Steam 未重启；[修复与实测记录](outputs/2026-11-11-按平台入库修复与实测.md)。

## 运行

打开 `outputs/Fluent Steam Mac.app`。开发时执行：

```sh
./script/build_and_run.sh --verify
./script/test.sh
python3 script/test_worker.py
```

Codex 的 Run 按钮也已配置。`--build` 仅打包，`--debug` 启动 lldb，`--logs` 查看运行日志。首次构建需要 CMake，并通过网络恢复 ZIPFoundation 0.9.20、SteamKit2 3.4.0、固定版本的 Dobby、.NET 8 macOS ARM64 / Windows x86 运行时。打包后不需要用户安装 .NET。应用采用本机临时签名，没有 Apple 开发者公证。

## 使用

1. 在“运行环境”确认 Steam 数据目录、macSteam 和 NotProton 已安装。可检查和下载官方 macSteam/NotProton，校验摘要、签名及当前 Steam 兼容数据；也可选择本机官方 companion app，提供备份安装、更新、内核卸载和恢复。内核操作要求 macOS 15+ 且 Steam / Wine 工具已退出。
2. 在“搜索入库”查找游戏并点击“一键入库”，自动获取、补齐并检查内容。也可拖入 Lua / ZIP / TAR / 7z / RAR。
3. 完整的新游戏直接入库；手动导入、内容缺项或替换已有 Lua 时显示预览，核对后点击“导入并启用”。支持的内容转换为 macSteam `config.yaml`。重启 Steam 后检查游戏库。
4. Windows 游戏继续由 Steam 中所选的 NotProton 兼容工具运行。详情页可打开对应前缀、Wine 配置和日志。

## 0.2.19 联机补丁验证

1. 在“联机补丁”选择补丁文件目录、目标游戏和实际 Windows `.exe`。选择 NotProton 自动定位前缀，或指定 CrossOver.app 与游戏所在容器。原生 Mac / ARM Windows / 架构混杂或不匹配的补丁拒绝部署。
2. 仅支持已初始化的 64 位 Windows 容器，可在其中运行 x86 或 x64 游戏；纯 32 位容器不支持当前 x64 模块检查助手。
3. 关闭 Steam 及该容器的全部 Windows 程序，再预览和备份部署。Wine DLL 覆盖按程序文件名生效，同容器的同名程序共享该设置；原注册表随补丁备份。
4. 部署后自行启动游戏，在该部署记录点击“检查补丁加载”。助手只读枚举该容器的进程及模块，不启动游戏、不向游戏注入 DLL、不修改游戏内存。按完整文件身份识别，检查前后核对补丁与程序摘要，显示结果和检查时间；结果不是实时监控。
5. 未观察到、部分加载、多个匹配进程、文件改变或不完整清单均不报告全部加载。旧记录缺少运行目标时保留还原，重新预览部署后才能检查。数据型补丁没有 DLL 时不能用模块检查验证。

## 0.2.17 云存档管理

“存档与备份 → 云服务设置”：在线服务从远端游戏行点击“预览 / 备份 / 删除”；本地或文件夹服务选择账号和游戏/AppID 后预览。先保存服务配置，关闭游戏与 Steam，并停止其他设备写入。预览显示选定账号和游戏的全部目标；完成备份与回读校验后才开放删除，再次确认后执行并回查。

备份位于 `~/Library/Application Support/FluentSteamMac/CloudDeleteBackups/`，保留本地原路径、文件内容、远端原始对象及 SHA-256。源数据、配置或备份改变会拒绝继续；远端部分删除失败时保留本地缓存和备份并报告状态。云端删除不跨设备原子化，不清除对象版本历史；远端备份恢复需手动上传。真实外部云账号未在本轮使用。

## 数据位置和写入方式

- 配置、Lua、缓存和事务备份：`~/Library/Application Support/FluentSteamMac/`
- macSteam：`~/Library/Application Support/macsteam/config.yaml`
- Steam：`~/Library/Application Support/Steam/`
- NotProton：`~/Library/Application Support/notproton/`
- Lua 设置提供迁移开关；更改或重置云文件夹路径会先复制校验再保存配置。同名冲突不会覆盖，原目录保留。其他路径设置不自动搬迁内容。

启动应用读取现有 Steam/macSteam 文件，并可获取名称缓存；自动广播模式还会备份并同步已启用主游戏的名称注释。实际导入、禁用、账号切换等由用户在界面中发起。所有受管文件修改先保存备份及 SHA-256，再原子替换；批次失败回滚。写入 macSteam 配置前检查文件是否被其他应用修改。现有 macSteam 内核限制 256 个 depot key 组、每组 64 个 depot，超限会拒绝写入而不是静默截断。

不会自动读取密码或执行导入的 Lua。在线登录由用户发起；手动输入的密码/验证码仅用于 SteamKit 会话，成功后的令牌保存在 macOS 钥匙串。本机登录仅在点击所选账号后读取其 Steam 缓存，不修改原缓存。macSteam 会重新加载配置，但 Steam 游戏库状态可能需要重启才能同步。

### 0.2.6：参照原版的兼容广播

67项核心测试通过，涵盖完整隔离入库/延后应用/还原与竞争条件。实际新版界面已验证，更新期间Steam PID不变；没有为验收此自动功能新加实机游戏。此前荒岛求生的单项手动修复已取得正确Windows下载清单，实际下载完成/游戏启动仍未验收。原生扩展保持0.2.6相同内容，无需重新部署。

### 0.2.10：自动成就准备与在线云存档

新入库或重新启用的主游戏进入持久成就准备队列。Steam 登录时取得公开定义，退出后再以备份事务应用；从 Fluent 启动 Steam 前也会处理。无定义、网络失败、游戏移除、手动关闭和运行中配置变化均有保护。不会批量接管现有游戏，也不会自动解锁成就。后续正常游玩由游戏自己的 Steam API 触发成就。

修复显式回锁修订号使后续原生缓存新解锁一直被忽略的问题：保留旧状态过滤，仅接受晚于回锁时间的新解锁；与回锁同秒的缓存时间无法区分，继续等待明确提交。独立原生测试先复现旧版失败，再验证新行为及旧状态不复活。实际《深空当铺》自带 `steam_api64.dll` 经 NotProton 返回 `EResult=1`，读到 21 项。用户正常改变物品标签，解锁「下层特供」并确认弹窗；原生记录捕获 0→1，独立只读回查确认仅这一项新增，保留此次真实进度。首次游戏启动曾报 Steam API 初始化失败，重开游戏后成功，根因仍待排查。

本轮 103 项 Swift 测试、15 个隔离 worker 场景、原生 schema/回锁/新解锁、云存储协议、OAuth 回调和库归属回归通过。RAR5 stored 格式补充完整导入/还原、CRC 损坏与路径穿越检查；其他 RAR5 压缩算法、加密及分卷未覆盖。好友端通知、实体双设备、扫码导出等仍需对应条件验收。
